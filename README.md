# Сигналы и обработчики: событийное взаимодействие объектов на C++

Курсовая работа по дисциплине «Объектно-ориентированное программирование» (РТУ МИРЭА).
Программа строит иерархическое дерево объектов и организует обмен сообщениями
между ними по механизму сигналов и обработчиков — по сути, это паттерн
«Наблюдатель» на указателях на методы классов.

## Что умеет программа

- **Дерево объектов.** Объекты шести классов создаются по входным данным и
  образуют иерархию «родитель — подчинённые». Объект находится по пути:
  абсолютному (`/object_s2/object_s4`), относительному, по имени в ветке (`.name`)
  или по имени во всём дереве (`//name`).
- **Связи «сигнал → обработчик».** Сигнал одного объекта связывается с обработчиком
  другого (`set_connection`); связь можно удалить (`remove_connection`), дубли не создаются.
- **Отправка сигнала с сообщением** (`emit_signal`). Сигнал дописывает к тексту номер
  класса отправителя, затем сообщение получают все подключённые обработчики.
- **Состояния объектов.** Отключённый объект (состояние 0) не отправляет и не принимает
  сигналы; отключение распространяется на всю ветку.
- **Команды:** `EMIT`, `SET_CONNECT`, `DELETE_CONNECT`, `SET_CONDITION`, `END`.

## Устройство

| Файл | Назначение |
| --- | --- |
| `src/cl_base.h/.cpp` | Базовый класс: дерево объектов, поиск по пути, состояния, связи и отправка сигналов |
| `src/application.h/.cpp` | Корневой объект: построение дерева по входным данным и цикл обработки команд |
| `src/cl_2` … `src/cl_6` | Классы объектов дерева со своими методами сигнала и обработчика |
| `src/main.cpp` | Точка входа |

Указатели на методы-сигналы и методы-обработчики хранятся в базовом классе через
`typedef void (cl_base::*TYPE_SIGNAL)(string&)`; по номеру класса объекта программа
выбирает нужный метод (`class_num_to_signal`, `class_num_to_handler`).

## Сборка и запуск

```bash
make          # сборка
make test     # прогон теста из курсовой и сравнение с ожидаемым выводом
./app < tests/input.txt
```

Пример вывода (`tests/expected_output.txt`):

```
Object tree
appls_root
    object_s1
        object_s7
    object_s2
        object_s4
        object_s6
    object_s13
Signal from /object_s2/object_s4
Signal to /object_s2/object_s6 Text:  Send message 1 (class: 4)
Signal to / Text:  Send message 1 (class: 4)
...
```

Программа проверялась в системе автоматического тестирования АСО «Аврора»,
поэтому формат ввода и вывода строго фиксирован.

## Что можно улучшить

- Сделать деструктор `cl_base` виртуальным (`virtual ~cl_base()`): объекты
  удаляются через указатель на базовый класс.
- Освобождать память, выделенную под связи (`connects`), в деструкторе.
- Хранить детей в `std::unique_ptr` вместо сырых указателей.
